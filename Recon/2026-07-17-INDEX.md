## Cross-project patterns found (the highest-value output of this pass)

1. **Clerk + Supabase is the company's de facto default SaaS starter
   stack** — independently used in `tapin`, `cinevault`, `step3-ai`, and
   likely `formflow`. Four citations. Strong enough to name explicitly in
   `patterns.md` as a validated default, not a coincidence.
2. **One-time purchase over subscription, explicitly reasoned as a
   trust/billing-anxiety decision** — `tiny-world` and `lights-out`
   independently reached the identical conclusion for the identical reason.
3. **A dedicated per-project file documenting AI-agent build gotchas/
   decisions before or during building** — `lights-out/planning/decisions.md`,
   `tiny-world/planning/decisions.md`, `RadialNest_PROMPT.md`. Three
   independent instances. This is already a real, working habit — the
   Debrief/lessons apparatus in HQ is formalizing something that already
   happens organically per-project.
4. **Vanilla HTML/CSS/JS + GitHub Pages for small client marketing sites**
   — `precision-maintenance` and `projectstack` share the exact shape.
5. **A pre-HQ `Agents/` CEO-harness folder was deployed to multiple
   projects**, not just this repo — found in `tiny-world` and `lights-out`.
   Real evidence of how the pattern was actually used before HQ existed.

## What to flag to the user

**Most consequential:** `projectstack` (and by extension `precision-maintenance`,
`tapin`) revealed a real business — "ProjectStack Web Solutions," with its
own GitHub organization (`projectstack-cc`) hosting what look like live,
possibly-revenue-generating client sites — **that Company Intelligence
currently has zero record of.** `founder-profile.md` and
`strategic-direction.md` both frame the $5,000/mo target as coming from
future opportunities to be found and built. If this business already
generates real revenue, that's a materially different starting position
than "zero revenue, zero operational history" (the headline finding of
yesterday's audit) — worth a direct conversation before the next
Opportunity Court session, not silently reconciled by an agent.

**Second most consequential:** `step3-ai`/"video-to-manual" is the most
complete, closest-to-shippable product found in this entire sweep — full
Stripe payments, Clerk auth, Supabase, a defined conversion pipeline. It
sits with no visible activity checked. Worth a deliberate look before
spending more Opportunity Court cycles hunting new ideas.

**Worth a decision, not urgent:** `packslip-pro` matches a real
`coo`-relevant opportunity category (Shopify + document automation) and
stalled at scaffold stage — revive or formally close out.
`pdf-tools` (GitHub-only, 127 commits) matches the same document-automation
interest and is far more developed than `packslip-pro` — check this one
first if document/PDF automation comes up again as an opportunity.

**Governance gap surfaced, not fixed:** `erp-lite` is XPanda Foam company
data (same company as the firewalled `xpanda-ops-platform`), but the
Constitution's ERP Firewall (Rule 6) names only `xpanda-ops-platform`
specifically. This report treated `erp-lite` with the same caution
anyway, but the rule's wording has a real gap worth fixing —
recommend "XPanda Foam company projects" instead of naming one repo.

**Minor:** the founder's git/GitHub identity is split between a personal
account (`Zer0Flaw`) and a business org (`projectstack-cc`) — several
repos' local remotes still point at the old personal-account URL (GitHub
redirects them, so nothing is broken, but it's worth knowing which
identity actually owns what going forward).
