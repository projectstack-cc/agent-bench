# Mission Brief: eclipse-circuit

## Mission Objectives

Build Eclipse Circuit — a 2.5D turn-based RPG, PC-first with mobile
compatibility maintained throughout (`Projects/Eclipse Circuit/
planning/decisions.md`, 2026-07-30) — from its current pre-production
state through to a playable, beta-testable PC build, well before any
mobile launch is considered. Full scope lives in `Projects/Eclipse
Circuit/planning/PRD.md` and `roadmap.md` — not repeated here.

## Success Metrics

**Deliberately open-ended, not a single closing bar.** This is
project-level HQ integration, not a bounded milestone pilot like
`auditsafeai-brc-pilot` — `Deployments/README.md` and
`agent-librarian.md` both define a mission as a bounded engagement with
a debrief, and this deployment doesn't fit that shape cleanly (flagged
to the founder directly, 2026-07-30; his call was to proceed this way
anyway). Progress is tracked through `Projects/Eclipse Circuit/
planning/roadmap.md`'s phase gates instead — currently Phase 3
(Concept art), startable. A `debrief.md` gets written here if and when
a natural project milestone closes (e.g. a playable PC vertical slice),
not on a fixed schedule.

## Constraints

- PC-first; mobile compatibility maintained, not a mobile-first design.
- Founder-driven creative project — did not clear an Opportunity Court
  pass. Canon, story, and art decisions require the founder directly;
  never invented unilaterally to fill a gap (`PRD.md`'s standing rule).
- Its own independent git repo (`Projects/Eclipse Circuit/`) — this
  Deployment folder is reference + delta only, per `Deployments/
  README.md`'s core rule, never a duplicate of that repo's content.
- Its own embedded runtime agents (`narrativeos/agents/` — the
  Xyril/Aelis/Marrow personas NarrativeOS itself calls) stay distinct
  from this roster, same distinction `Projects/AuditSafeAI/agents/
  README.md` draws for its own product-embedded agents.
